# عدالت فیلتر — Edalat Filter Platform

پلتفرم تخصصی فیلتر و قطعات مصرفی خودرو: فروشگاه آنلاین (خرده و عمده)، مرجع اطلاعات خودرو،
جست‌وجوی هوشمند (متن / کد فنی / صوت / تصویر) و ثبت سفارش تولید با برند اختصاصی.

> Source of truth برای رفتار محصول: PRD پروژه.
> Source of truth برای طراحی بصری: فایل Figma «Filter-site».

---

## ساختار پروژه

```text
edalat-filter/
├── apps/
│   ├── web/          Next.js 15 (App Router) + TypeScript + Tailwind v4 — فارسی/RTL
│   └── api/          NestJS 11 + Prisma + PostgreSQL
├── packages/
│   └── shared/       تایپ‌ها، enumها و ابزارهای متن فارسی (مشترک بین web و api)
└── docker-compose.yml  PostgreSQL + Redis + MinIO
```

`packages/shared` عمداً بین دو اپ مشترک است: نرمال‌سازی متن فارسی باید در ایندکس (سمت API)
و در ورودی کاربر (سمت وب) **دقیقاً یکسان** باشد، وگرنه نتایج جست‌وجو از هم فاصله می‌گیرند.

## راه‌اندازی

```bash
# ۱. نصب وابستگی‌ها (npm workspaces)
npm install

# ۲. بالا آوردن دیتابیس و سرویس‌های جانبی
docker compose up -d

# ۳. تنظیم متغیرهای محیطی
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local

# ۴. ساخت پکیج مشترک، سپس مایگریشن و داده نمونه
npm run build --workspace @edalat/shared
npm run db:migrate
npm run db:seed

# ۵. اجرا (api روی 4000، web روی 3000)
npm run dev
```

- وب‌سایت: <http://localhost:3000>
- مستندات API (Swagger): <http://localhost:4000/api/docs>

> **نکته:** `packages/shared` باید قبل از دو اپ دیگر build شود؛ هر دو اپ خروجی `dist` آن را مصرف می‌کنند.

## تصمیم‌های معماری

### قیمت‌گذاری — تنها یک مسیر

`PricingService.quote()` تنها جایی است که قیمت نهایی تعیین می‌شود. صفحه محصول، سبد خرید و
Checkout همگی از همان تابع عبور می‌کنند؛ بنابراین قیمتی که کاربر می‌بیند دقیقاً همان قیمتی است
که فاکتور می‌شود. Backend هرگز قیمت ارسالی از Frontend را قبول نمی‌کند (PRD §32، §77).

قیمت عمده **پلکانی** است، نه یک عدد ثابت:

```text
۲۰ – ۴۹    ۲۷۵٬۰۰۰
۵۰ – ۹۹    ۲۶۰٬۰۰۰
۱۰۰+       ۲۴۵٬۰۰۰
```

آخرین پله می‌تواند `maxQuantity = null` باشد (یعنی «و بیشتر»).

### سازگاری خودرو — رابطه واقعی، نه متن

`ProductVehicleCompatibility` یک جدول واسط کامل است و همان جدول هم بازه تعویض مخصوص هر
جفت (محصول، خودرو) را نگه می‌دارد. همین ساختار سه قابلیت را هم‌زمان می‌دهد:

- «چه قطعاتی به این خودرو می‌خورد؟» → `GET /vehicles/{id}/products`
- «این قطعه روی چه خودروهایی می‌نشیند؟» → `GET /products/{id}/vehicles`
- «این قطعه با چه خودروهای دیگری مشترک است؟» → `GET /products/{slug}/shared-with/{vehicleId}`

### جست‌وجو — سطل‌بندی به‌جای یک OR بزرگ

هر منبع تطبیق سطل جداگانه‌ای با امتیاز خودش دارد (کد فنی دقیق ۱۰۰۰ → توضیحات ۱۰۰). نتیجه با
`id` ادغام می‌شود و بالاترین امتیاز می‌ماند. با این کار یک تطبیق دقیق کد فنی هرگز زیر انبوهی از
تطبیق‌های فازی نام دفن نمی‌شود.

متن فارسی قبل از ایندکس و قبل از کوئری نرمال می‌شود: `ي→ی`، `ك→ک`، حذف اعراب و کشیده،
تبدیل نیم‌فاصله به فاصله و ارقام فارسی به لاتین.

هر جست‌وجو در `SearchQueryLog` ثبت می‌شود — مخصوصاً جست‌وجوهای بدون نتیجه، که مستقیم به
تصمیم «چه محصولی به انبار اضافه شود» تبدیل می‌شوند (PRD §68).

### درخواست تصویری — انسان امروز، AI فردا

در MVP کارشناس قطعه را از روی عکس شناسایی می‌کند. رکورد از همین حالا فیلدهایی را دارد که یک
خط لوله AI بعداً پر می‌کند (`identifiedProductId`، `possibleCode`)، پس افزودن Computer Vision
یعنی نوشتن در همان رکوردها، نه بازطراحی مدل داده (PRD Rule 5).

### RTL از پایه

`dir="rtl"` روی `<html>` تعریف شده و چیدمان‌ها با ویژگی‌های منطقی (`ms-`, `me-`, `inset-inline`)
نوشته شده‌اند. کدهای فنی و اعداد با کلاس `.ltr-num` ایزوله می‌شوند تا `LF16352` برعکس رندر نشود.

## طراحی

توکن‌های استخراج‌شده از Figma در `apps/web/src/app/globals.css`:

| توکن | مقدار | کاربرد |
| --- | --- | --- |
| `brand-500` | `#FEDD00` | دکمه‌های اصلی، تأکید |
| `ink-600` | `#4E4B47` | سطوح تیره، فوتر، هدر |
| `sand` | `#E1DDDB` | نوار جست‌وجو، دکمه ثانویه |
| `surface` | `#EDEDED` | کارت محصول و دسته‌بندی |

فونت طراحی **IRANYekanX** است (لایسنس‌دار). فایل‌های `.woff2` را در
`apps/web/public/fonts/` بگذارید تا خودکار فعال شود؛ تا آن زمان **Vazirmatn** (متن‌باز،
self-hosted) جایگزین می‌شود.

## وضعیت پیاده‌سازی

**آماده**

- مدل داده کامل مطابق PRD (§42–§51) + مایگریشن + داده نمونه
- قیمت‌گذاری خرده/عمده پلکانی با اعتبارسنجی سمت سرور + تست واحد
- کاتالوگ محصولات، دسته‌بندی، برند
- بانک اطلاعات خودرو + سازگاری + سازگاری مشترک
- موتور جست‌وجو با رتبه‌بندی و تحمل خطای فارسی + پیشنهاد تایپی
- احراز هویت با شماره موبایل و OTP (JWT + refresh چرخشی)
- سبد خرید و Checkout با رزرو اتمی موجودی
- ثبت درخواست تولید با برند اختصاصی و درخواست شناسایی تصویری
- صفحه اصلی مطابق Figma، ریسپانسیو، RTL

**مرحله بعد**

- صفحات فروشگاه، جزئیات محصول، سبد خرید، خودروها، داشبورد کاربر
- پنل ادمین
- آپلود فایل روی S3/MinIO و اتصال درگاه پرداخت
- ارسال پیامک OTP از طریق سرویس‌دهنده واقعی
